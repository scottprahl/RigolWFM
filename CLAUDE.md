## Project Overview

RigolWFM is a Python library and CLI tool for parsing and converting oscilloscope waveform files. Rigol is the original and best-covered family (DS1000B/C/D/E/Z, DS2000, DS4000, DS6000, DHO800/1000, MSO5000/7000/8000), and it also reads Siglent `.bin`, Tektronix `.wfm`/`.isf`, LeCroy `.trc`, Agilent/Keysight `AGxx` `.bin`, Rohde & Schwarz RTP `.bin`, and Yokogawa `.wfm`/`.wvf` files.

Binary formats are described in [Kaitai Struct](https://kaitai.io/) YAML files (`.ksy`), which are compiled into Python parsers. The auto-generated parser files (`wfm1000e.py`, `wfm1000z.py`, etc.) must not be hand-edited.

## Commands

All commands use `uv` as the package manager. Run from the repo root.

```bash
# Setup
make venv          # Install all dependencies (uv-based)
make all           # Regenerate Python parsers from .ksy files

# Testing
make test          # Run pytest + conversion tests
make note-test     # Run Jupyter notebook tests
pytest tests/test_e.py                    # Single test file
pytest tests/test_e.py::test_ds1102e_...  # Single test

# Linting
make ruff-check    # Run ruff linter
make pylint-check  # Run pylint
make yaml-check    # Lint .ksy and workflow YAML files
make rst-check     # Lint .rst documentation files

# Development
make lab           # Launch JupyterLab
make html          # Build Sphinx documentation

# Release checks (runs everything)
make rcheck
```

## Architecture

**Entry points:**
- Python API: `RigolWFM.wfm.Wfm.from_file(filename, model)` or `.from_url(url, model)`
- CLI: `wfmconvert <scope> <format> <file>` (implemented in `RigolWFM/wfmconvert.py`)

**Data flow:**
1. `wfm.py` — `Wfm` class dispatches to the right parser based on the `model` string (e.g. `"E"` → DS1000E)
2. Scope-specific parser (e.g. `wfm1000e.py`) — auto-generated by kaitai-struct-compiler from `ksy/` files; reads binary data into structured objects
3. `channel.py` — `Channel` class provides a uniform interface over all scope families; converts raw ADC counts to scaled `volts` and `times` numpy arrays
4. `wfm.py` — output methods (`csv()`, `wav()`, `plot()`, `sigrokcsv()`) operate on the `Channel` list

**File layout:**
- `RigolWFM/wfm.py` — main API, `Wfm` class, exception types
- `RigolWFM/channel.py` — `Channel` class with per-family `ds1000e()`, `ds1000z()`, etc. static parsers
- `RigolWFM/wfm*.py`, `RigolWFM/bin*.py` — auto-generated KaitaiStruct parsers (do not edit)
- `RigolWFM/mso5000.py`, `RigolWFM/dho.py` — hand-written parsers for binary formats
- `ksy/` — Kaitai Struct source files (edit these, not the generated `.py` files)
- `tests/files/wfm/` — sample `.wfm` waveform files used in tests
- `tests/files/wfm-tek/` — real Tektronix `.wfm` captures (see `SOURCE.rst` there for provenance)
- `tests/files/bin/` — sample `.bin` binary capture files used in tests
- `tests/files/trc/` — sample LeCroy `.trc` and `.000` files used in tests
- `tests/expected_info/` — golden output files for snapshot tests

**Adding a new scope family:**
1. Write a `.ksy` format description in `ksy/`
2. Run `make all` to regenerate the Python parser
3. Add a `channel.py` method for the new family
4. Register the model strings in `wfm.py`
5. Add snapshot tests in `tests/`

## Testing Approach

Tests are primarily snapshot-based: `wfmconvert <scope> info <file>` output is compared against golden files in `tests/expected_info/`. Helper functions are in `tests/cli_helpers.py`. To update golden files after intentional format changes, delete the relevant expected output file and re-run the test (it will write a new one).

## Linting Notes

- Line length is 120 characters (ruff, pylint, black all configured to this)
- Docstrings follow Google style (ruff rule `D`)
- Auto-generated parser files (`wfm\d+\.py`, `bin\d+\.py`) are excluded from linting
